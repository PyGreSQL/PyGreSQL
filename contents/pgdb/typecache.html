TypeCache – The internal cache for database types¶

class pgdb.TypeCache¶

Added in version 5.0.

Changed in version 6.3: The class is now exported by the pgdb module.

The internal TypeCache of PyGreSQL is not part of the DB-API 2 standard, but is documented here in case you need full control and understanding of the internal handling of database types. Each connection has its own type cache, available as Connection.type_cache.

The TypeCache is essentially a dictionary mapping PostgreSQL internal type names and type OIDs to DB-API 2 “type codes” (which are also returned as the type_code field of the Cursor.description attribute).

Types are looked up in the database when they are not yet cached. Type names are taken literally, like the parts of table names in the classic module (see Table names): they are the internal names in the pg_type catalog such as int4 or _int4, not SQL type names such as integer or int[]. They can be enclosed in double quotes and qualified with a schema name, e.g. pg_catalog.int4. Names without a schema are looked up in the search path, and pg_temp stands for the temporary schema of the session. Names can also be passed as bytes in the client encoding. Looking up a type that does not exist never aborts the current transaction.

Changed in version 6.3: Before, qualified type names were parsed as SQL type names, and looking up a type that did not exist aborted the current transaction.

These type codes are strings which are equal to the PostgreSQL internal type name, but they also carry additional information about the associated PostgreSQL type in the following attributes:

  • oid – the OID of the type

  • len – the internal size

  • type – 'b' = base, 'c' = composite, …

  • category – 'A' = Array, 'B' = Boolean, …

  • delim – delimiter to be used when parsing arrays

  • relid – the table OID for composite types

  • base – the base type code for domains, None for other types

  • elem – the OID of the element type for array types

Domains take the attributes delim, relid and elem from their base type, resolved through domains over domains. Values of domain types are cast like values of their base types. A typecast set for the name of a domain is used for elements of arrays and fields of composite types with that domain type, but not for values of columns, since PostgreSQL reports these with the base type, which is also the type code in Cursor.description.

Changed in version 6.3: The base and elem attributes have been added.

For details, see the PostgreSQL documentation on pg_type.

In addition to the dictionary methods, the TypeCache provides the following methods:

TypeCache.get_fields(typ)¶

Get the names and types of the fields of composite types

Parameters:

typ (str or int) – PostgreSQL type name or OID of a composite type

Returns:

a list of named tuples with the name and the type (type code) of each field, or None if the type is not composite

Return type:

list or None

TypeCache.get_typecast(typ)¶

Get the cast function for the given database type

Parameters:

typ (str or int) – PostgreSQL type name, type code or OID

Returns:

the typecast function for the specified type

Return type:

function or None

TypeCache.set_typecast(typ, cast)¶

Set a typecast function for the given database type(s)

Parameters:

  • typ (str or list) – PostgreSQL type name or type code, or list of such

  • cast (callable or None) – the typecast function to be set for the specified type(s), or None to remove a typecast that has been set

The typecast function must take one string object as argument and return a Python object into which the PostgreSQL type shall be cast. If the function takes another parameter named connection, then the low-level pg.Connection underlying the current database connection will also be passed to the typecast function, like in the pg module. This may sometimes be necessary to look up certain database settings.

Changed in version 6.3: Before, the connection was only passed to a parameter named cnx, which is still supported.

Changing the typecast function for a type also affects fields of composite types with that type, even if values of these composite types have already been cast.

Typecasts are set for the names of types, so a typecast that you set applies to all types with that name in all schemas. The built-in default typecasts, however, are only used for base types, not for composite types, domains, enums and ranges that have the name of a built-in type. For composite types, domains and arrays without a typecast set for their name, the typecast is created from the types of the fields, the base type or the element type. These are looked up by their OIDs, so that this also works for types that are not in the search path and for types with the same name in different schemas. The typecasts for composite types are cached with their fields. After changing the fields, call TypeCache.reset_typecast(). Types that have been looked up by name stay cached under that name. After changing the search path, call the clear() method. This only affects lookups by name, values in query results are always cast according to the OIDs of their types.

TypeCache.reset_typecast([typ])¶

Reset the typecasts for the specified (or all) type(s) to their defaults

Parameters:

typ (str, list or None) – PostgreSQL type name or type code, or list of such, or None to reset all typecast functions

TypeCache.typecast(value, typ)¶

Cast the given value according to the given database type

Parameters:

  • value – the value to be cast, as returned by the database

  • typ (str or int) – PostgreSQL type name, type code or OID

Returns:

the cast value

Note

Note that the TypeCache is always bound to a database connection. You can also get, set and reset typecast functions on a global level using the functions pgdb.get_typecast(), pgdb.set_typecast() and pgdb.reset_typecast(). If you do this, running connections may continue to use typecast functions they have already cached, particularly for type names they have already used. To be sure that a global change is picked up, call TypeCache.reset_typecast() for these types on the Connection.type_cache objects of the running connections.
